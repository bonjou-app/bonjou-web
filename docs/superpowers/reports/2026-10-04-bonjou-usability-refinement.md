# Bonjou usability refinement — 4 October 2026

The approved illustrations and interactive sections remain in place. This pass applies the supplied UX references to concrete task behavior: preparing a file, recognizing its audience, approving a handoff, recovering from mistakes, and joining a room.

## References and method

- [Laws of UX](https://lawsofux.com/): choice clarity, recognizable controls, proximity of related information, and usable target sizes.
- [Nielsen's 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/): visible system status, natural language, user control, consistent mappings, prevention, recognition, and actionable error recovery.

Both references were opened during this pass. The issues below were observed in the current source and checked through browser regressions. Priority describes the consequence of an interaction mistake, not a measured frequency. This is a focused implementation review, not a user study or a claim of complete accessibility certification.

The final source review also caught a lower-priority feedback issue: a failed private message's error could appear under another conversation's draft. Chat failure feedback now follows the originating thread, while file-staging errors remain with the shared tray. The browser regression switches away from the failed draft, verifies that the unrelated conversation has no error, and switches back before retrying.

The final `e2e:accessibility` run also passed 16 whole-page Chrome scans across light/dark landing, mobile landing, onboarding, workspace, settings, palette, history, and populated room states. Axe detected no WCAG A/AA violations in those tested states.

The first extended staging run used an exact text locator that stopped matching once existing-file size was displayed alongside the reading status. The selector was corrected to target the status region; the full rerun passed. No production workaround was added.

Native WebRTC tests exercise local browser handoffs; they do not prove cross-network reachability or performance on physical phones. Browser gates and send failures are explicit test-only fault injections. Firefox, physical devices, and a manual screen-reader review were not exercised.
